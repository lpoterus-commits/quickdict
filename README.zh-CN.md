# 快捷查词助手 · QuickDict

**给韩语学习者的 macOS 取词工具。** 屏幕上任何地方的韩语——扫描版教材、PDF、视频字幕、网页、
别人发来的截图——框选或划词，立刻弹出词典释义。识别全部在本机完成，不联网、不上报、不记历史。

开箱即用，支持 **English / 中文 / 日本語 / 한국어 / Русский / Tiếng Việt / Italiano**，首次启动按系统语言自动配好。

语言: [English](README.md) · **中文** · [Русский](README.ru.md) · [Tiếng Việt](README.vi.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

[完整功能介绍](FEATURES.md)

## 和其他取词工具的区别

能从屏幕上读字的工具很多。这个的不同之处是——**它能把换行切断的韩语词拼回去**。

OCR 一段换行的文字时，行尾的词会被切成两半。`이성적인`（理性的）跨行后变成 `이` + `성적인`，
直接拼接就成了 `이 성적인`，意思完全变了。**原本分隔它们的空格被换行吃掉了，在像素上不存在。**

解决它撞了三堵墙：

| 尝试 | 结果 |
|---|---|
| 系统韩语拼写检查 | ✗ `그리느끼는` 这种随便拼的都判成词，只查谚文音节合法性 |
| NaturalLanguage 韩语分词器 | ✗ 只按空格切，不做形态素分析 |
| 纯几何（行末是否顶满） | △ 能分辨「换行」和「段落结束」，但分不清断点落在空格还是词中间 |

最终方案是三种信号组合：

1. **系统韩语词典**（`DCSCopyTextDefinition`）——把两半拼起来，看最长成词前缀有没有**越过接缝**。
   `이` + `성적인` → 词典查到 `이성적`（长度 3 > 上半的 1）→ 判定为断词。
2. **行末几何**——Vision 给的每行 bounding box，判断这行是被挤断的还是自然结束。
3. **韩语词尾表**——行首出现悬空的 `은` / `는` / `로서` / `하며` / `진다고`，只可能是上一行那个词的后半截。

拉丁文另走一路：英语拼写检查是真词典，`jum` + `ps` = `jumps` 靠查词判定，不用启发式。

**28 个端到端测试全部通过**，fixture 图片进仓库，跑的是真实 Vision OCR 而非桩数据。

词尾表**可以在配置里补充**，发现遗漏自己就能修，不用改代码也不用等新版本：

```jsonc
"koreanExtraParticles":  ["로부터", "에서부터"],
"koreanExtraStandalone": ["뭐"]
```

是**合并**而不是替换，内置表继续随版本更新。

### 判不了的时候会明说

`이성적인`（理性的）和 `이 성적인`（这个性方面的）**都是合法韩语**。断行正好落在中间时，
本地没有任何信号能分辨——只有上下文能判，那需要语言模型。

所以默认合并（合起来的用法频率高得多），但**把判过的位置报出来**：

```
已复制 87 字
⚠️ 这些地方合并了，但拆开写也讲得通：이성적인
```

实测每段文本报 0~1 处，不会变成噪音。

## 用法

| 快捷键 | 取字方式 | 动作 |
|---|---|---|
| `⌃⌥9` | 框选截图 + OCR | 查词，自动判语种 |
| `⌃⌥0` | 框选截图 + OCR | **智能拼行后只放剪贴板**，不查词（完全离线可用） |
| `⌃⌥8` | 框选截图 | **识别二维码/条码**，是网址就用浏览器打开 |
| `⌃⌥7` | 框选截图 + OCR | **朗读**——扫描版教材框一段直接听（先断词还原再读） |
| `⌘⌥D` | 当前选中的文字 | 查词，自动判语种 |
| `⌘⌥F` | **自己输入** | 空着打开查词窗口，什么都不用先选 |
| `⌘⌥Q` | 当前选中的文字 | **朗读**。没选中就重读上一段；正在读就停 |
| `⌘⌥N` | 当前选中的文字 | 直达 Naver（你那套语言的） |
| `⌘⌥K` | 当前选中的文字 | 直达 국어사전（韩韩） |
| `⌘⌥P` | 当前选中的文字 | 直达 Papago |
| `⌘⌥G` | 当前选中的文字 | 直达谷歌翻译 |

**截图类**管图片、PDF 扫描件、视频字幕这些选不中的字；**划词类**管能选中的文本，没有识别误差也更快；
**`⌘⌥F` 谁都不用**——直接开窗口自己敲，配好的词典（含本地文件和本地词典 App）在这里全都能用，
等于一个随叫随到的多词典查询器。

直达键是**按你那套语言实际有哪些词典生成的**，不会出现指向不存在词典的死键。

| 其他操作 | |
|---|---|
| 框选时按 esc | 取消截图 |
| `⌘1`…`⌘9` | 在结果窗口切换词典 |
| `⌘L` | 改识别到的词，回车重查 |
| `esc` / `⌘W` | 关闭窗口 |
| `⌘+` `⌘-` `⌘0` | 调字号。双指缩放也可以，比例会记住 |
| 黄灯 | 最小化到程序坞 |
| 🔊 按钮 | **离线朗读当前词**，按识别出的语种选嗓音；再按一次停止 |
| 罗盘按钮 | 把当前查询丢到默认浏览器 |
| 图钉按钮 | 常驻置顶。不按的话窗口只在弹出时浮在最上面，一点别的窗口就自动沉下去 |
| 再按一次 `⌘⌥F` | 把窗口叫回来，**内容原样保留**。菜单栏工具不进 ⌘Tab，这就是找回窗口的办法 |

朗读是从我自己用了很久的浏览器脚本（Tampermonkey）移植进来的，那套为学语言调出来的处理都在：
去符号只留停顿标点、空行分节停顿、诗歌换行并成短顿、**混排文本各读各的**——不只逐节，行内混排也按文字系统切开：
「사랑이라는 말，意思是爱」韩语段用韩语嗓音、中文段换中文嗓音；日语句子里的汉字不会被误当成中文（有假名就判日语）。
快捷键编辑器里还能把「朗读」配到**截图**上——框选扫描版教材直接听，这是浏览器版做不到的。
语言**不用提前设定**：谚文、汉字、假名、西里尔、希腊、希伯来、阿拉伯、泰文、天城文按码位直判，
拉丁语（意/法/越/西/德…）整句统计识别。嗓音用系统自带的（约四十种语言），没有对应嗓音的语言会静音跳过。
语速和「读不读数字」在配置文件里：`speechRate`（1.0 = 正常）、`speechSkipsNumbers`。

**记不住就按 `⌘?`** 调出内置说明书——内容按当前配置实时生成，改了快捷键或加了词典它会跟着变。

菜单栏里有：三个取词入口、打开查词窗口、查词语言、设置向导、快捷键设置、使用说明、编辑配置、重新载入配置、
清除浏览数据、开机自动启动、权限与识别语言自检。

## 安装

需要 **macOS 13.0+**，通用二进制（Apple Silicon 与 Intel 都支持）。

```bash
git clone https://github.com/lpoterus-commits/quickdict.git && cd quickdict
./build.sh install
```

只需要 Command Line Tools，**不需要完整 Xcode**，编译约一分钟。

**Windows 呢？** 暂时没有。这里每一项能力都是苹果的框架，所以是重写而不是移植——而且韩语断词还原依赖 macOS 自带的韩语词典，Windows 上没有对应的东西。[WINDOWS.md](WINDOWS.md) 是给想做这件事的人的交接文档：算法、试过并失败的三个方向、API 对照表，以及测试集（纯数据，可以直接拿去用）。

> 装出来叫 `QuickDict 3.app`，好和旧的 2.0 并存。想叫回 `QuickDict` 就改 `build.sh` 里的 `APP_NAME`。

### 如果打不开

下载来的 zip，macOS 会拦下没有经过 Apple 公证的 app，提示「**「QuickDict 3」已损坏，无法打开**」。
**软件没有损坏**——macOS 给所有从网上来的文件都贴了这个标记。公证要每年 $99，这个项目没花这笔钱。

三条路，挑一条：

**1. 自己编译**（上面那条命令）。本地编译出来的文件根本不会被贴标记，最干净。

**2. 下载后跑一行命令。** 在终端里粘贴一次，之后照常双击打开：

```bash
xattr -dr com.apple.quarantine "/Applications/QuickDict 3.app"
```

**只需要做一次**，标记不会再回来。清除它不会改动或削弱软件：代码签名依然有效，所有功能和自己编译出来的完全一样。

**3. 让别人拷给你。** 这个标记是浏览器、邮件、AirDrop 打上的。**从 U 盘或移动硬盘拷过来的文件完全没有标记**，
双击就能开，不用碰终端。

### 两个权限

都在 系统设置 → 隐私与安全性 里勾选，**勾完必须重启 App**（macOS 的权限只对新进程生效）。
首次启动的设置向导会引导你完成，并实时显示状态。

| 权限 | 用途 | 不给会怎样 |
|---|---|---|
| 屏幕录制 | 框选截图 | 所有截图类快捷键失效 |
| 辅助功能 | 读取其他 App 里选中的文字 | 所有划词类快捷键失效 |

| | Naver 词典 | 翻译器目标 |
|---|---|---|
| English | `en.dict.naver.com` | `en` |
| 中文 | `zh.dict.naver.com` | `zh-CN` |
| 日本語 | `ja.dict.naver.com` | `ja` |
| 한국어 | `ko.dict.naver.com` | `ko` |
| Русский | `dict.naver.com/rukodict` | `ru` |
| Tiếng Việt | `dict.naver.com/vikodict` | `vi` |
| Italiano | `dict.naver.com/itkodict` | `it` |

### 自己指定用哪个词典

有两个轴决定打开什么：

- **查词语言** —— 一种，释义落在这。菜单栏 →「查词语言」
- **还要查哪些语言** —— 你会遇到哪些外语。菜单栏 →「还要查哪些语言」，想勾几个勾几个

韩语走 Naver 的双语词典，其余勾选的语言各配一个 Glosbe（`glosbe.com/<源>/<目标>/<词>`），
任意语言对都有。**框选意大利语就开意语词典，框选韩语就开 Naver，不用手动切。**

**想用别的站点？** 菜单栏 →「**词典设置…**」，点「**＋ 添加**」，然后选一种：

| 选哪种 | 接下来 |
|---|---|
| **常用词典** | 从清单里挑（Naver、Papago、Glosbe、谷歌…），都是验证过能用的 |
| **本地文件** | 弹出文件选择框，挑一个 `.md`。自己整理的笔记就走这条 |
| **本地词典 App** | 从本机**真的装了**的那些里面挑 |
| **自己填网址** | 留给想完全自定义的人，这里才需要写 `{q}` |

**不用手打网址**，列表里显示的也不是网址，而是「网页 · zh.dict.naver.com」「本地文件 · 我的语法笔记.md」这样一句话。

「命中语言」是个**勾选菜单**：勾上哪几种语言，识别到它就自动跳这本词典；
「只能手动切」表示不自动命中，「兜底」表示接住其余全部。

不想点界面的话，配置文件里是同一件事：

```jsonc
{
  "id": "yihan",                              // 唯一标识，随便起
  "name": "意汉",                              // 按钮上显示的名字
  "languages": ["it"],                        // 意大利语现在归它，不再用 Glosbe
  "url": "https://www.yihan.it/{q}"           // {q} 是查询词的位置
}
```

改完点「重新载入配置」。可选字段：

| 字段 | 含义 |
|---|---|
| `languages` | 识别到哪些语种时自动命中。`"*"` 是兜底，`[]` 表示只能手动切 |
| `suffix` | URL 编码**之前**拼到查询词后面，适合搜索引擎和 AI 提问模板 |
| `external` | 填 `true` 就交给系统打开而不是内嵌窗口，用于依赖登录态的站点 |

**你加的词典在任何操作下都保留**——换母语、勾选新语言，都不会动它。

### 用本地词典软件代替网页

装了词典软件的话，查词可以直接跳到它而不是开网页。菜单栏 →「**本地词典 App**」
会列出本机**真的装了**的那些让你勾，没装的不显示。

原理是这类软件都注册了自己的 URL scheme，而标了 `external` 的项会交给系统打开，不走内嵌窗口：

```jsonc
{ "id": "local-eudic", "name": "Eudic", "languages": ["en"],
  "url": "eudic://dict/{q}", "external": true }
```

勾上后默认是**只能手动切**——词典软件通常什么语言都能查，该让它管哪一种是你的决定。
给它写上 `languages` 就自动命中，而且会完全接管那个语言。

### 查自己整理的资料

**自己写的 Markdown 笔记可以直接当词典查**，不用先转格式，全程离线。

「词典设置…」→「＋ 添加」→ 选「**本地文件**」，挑你的 `.md`（选文件夹也行，里面所有 `.md` 都算）。

**笔记分好几份不用配好几条词典。** 结果页面顶上有一条资料管理条：

```
语法笔记一 4 ×   语法笔记二 4 ×   语法笔记三 3 ×   ＋ 添加资料
```

- **数字是这次查询在各份资料里的命中数**，点名字直接跳到那一组
- **✕ 移除、＋ 添加**，都在这儿做，不用回设置窗口
- 结果**按来源分组折叠**，第一组展开，其余点开即看

几份资料难免有重复的条目（实测三份表跨表重复 65 个语法点）。
分组之后重复不再挤在一起，**反倒方便对照同一个语法点的不同写法**。

改完笔记直接查就是新的，**不用重新生成任何东西**（App 发现源文件变了会自己重转）。

**笔记要长什么样**

**普通笔记不用管格式**——最深的那一级标题就是词条，浅的都当分组：

```markdown
# 派生词缀词典        ← 分册
## 第一组 空·虚·裸     ← 分组
### -자마자〔一…就…〕   ← 词条（最深一级）
```

想让词条落在 `##`，那就别用 `###` 做小节。

**分册分章的大表**可以给条目编号，这样章节标题不会被误认成词条：

```markdown
## 001｜A/V-거든(요)          ← 编号｜形式
### 1. V-자마자               ### 编号. 形式
```

有 `## 正文` 这一行的话，之前的目录部分会被跳过。
一条都解析不出来时会显示提示页，**并列出它实际看到的标题**，对照着改就行。

**为什么不能直接读 .md**

试过：WebKit 把 `.md` 当非 UTF-8 显示成乱码、Markdown 语法原样露在页面上、
`?q=` 没人处理等于把整个文件倒出来。三处同时垮。

更根本的是**搜索要靠转换时算出来的东西**。韩语查的是变形后的词：
看到 `가기로 했어요` 要找到 `V-기로 하다`。标签里的词性标记（`A/V-`）、可选成分（`(요)`）、
音变标记（`(으)ㄹ`）都不会出现在真实文本里，得先剥掉；词典形 `-하다` 要按谚文音节
推出 `했 / 해`。活用是按音节结构算的，所以 `버리다`、`마시다` 这些不用登记就能用。

**搜索覆盖全文**：语法形式、释义、分类、以及**正文里的每一句**（例句、辨析、说明）。
搜「戒烟」能找到例句里写着「담배를 끊기로 결심했어요」的那几条，命中处会标黄。

正文命中排在结构性命中之后并标上「正文命中」—— 常见词在几十条例句里出现，
不压低权重的话真正相关的那条会被淹掉。

> 想把笔记做成一个**能单独分享**的 HTML（给没装本 App 的人），
> 仓库里有 `Tools/notes2html.py` 做这件事。日常使用不需要它。

### 给预设加一种语言

Naver 词典覆盖 67 种语言，但 URL 有**两种形态**，这点很容易踩坑：

- **英 / 中 / 日 / 韩**：独立子域名 `https://<code>.dict.naver.com/#/search?query={q}`
- **其余全部**：同一域名下的路径 `https://dict.naver.com/<code>kodict/#/search?query={q}`

在 `DictionaryPresets.all` 里加一条即可，词典集、对应快捷键、内置说明书都会跟着变。
Naver 没有对应语言时，Naver 形态填 `.none`——韩韩词典顶上来接管自动路由，母语靠谷歌翻译兜底。

## 配置

`~/Library/Application Support/com.quickdict.app/config.json`，改完在菜单里点「重新载入配置」即可生效。

```jsonc
{
  // 快捷键。key 直接写键名，source 是 screenshot / selection，
  // action 是 lookup / clipboard / qrcode，dictionary 是 "auto" 或某个词典 id
  "hotkeys": [ … ],

  // 词典。{q} 是查询词的位置；suffix 在编码前拼到词后面；
  // languages 决定何时自动命中（"*" 兜底，空数组只能手动切）；
  // external: true 表示跳默认浏览器（用于依赖登录态的站点，如 Google AI 模式）
  "dictionaries": [ … ],

  "autoDetectLanguage": true,      // 必须开，否则拉丁语与 CJK 混排时识别不出 CJK
  "collapseWhitespaceToSpace": true,
  "alwaysOnTop": false,
  "clearDataOnQuit": true,         // 退出时清空内嵌窗口的 Cookie / localStorage
  "qrConfirmBeforeOpen": false,    // 二维码链接打开前先确认
  "koreanExtraParticles": [],      // 断词还原的词尾表补充
  "koreanExtraStandalone": []
}
```

## 隐私

识别层全部本地：Vision OCR、Vision 条码、NaturalLanguage 判语种、系统词典、几何计算。
实测运行期间**零网络连接**，源码里 `URLSession` 出现 **0 次**。

只有「打开词典网页」需要联网，那本来就是网页。`⌃⌥0` 截图转文字**完全离线可用**。

App 自身不记录任何查询历史；内嵌窗口的 Cookie 和 localStorage 默认退出即清
（词典网站会往那里塞「最近搜索」，实测两三天能涨到 100MB+）。

## 代码结构

约 3300 行 Swift，无第三方依赖。

| 文件 | 职责 |
|---|---|
| `LineJoiner.swift` | 智能拼行：词典 + 几何 + 词尾表 |
| `DictionaryPresets.swift` | 各语言的词典集与对应默认快捷键 |
| `Onboarding.swift` | 首次启动向导、权限引导、Gatekeeper 自检 |
| `LanguageRouter.swift` | 字符集硬路由 + 拉丁语统计识别 |
| `OCR.swift` / `QRCode.swift` | Vision 文字与条码识别 |
| `SelectionReader.swift` | 读选中文字：AX 直读 + ⌘C 回落 |
| `HotKeyManager.swift` | Carbon 全局热键（不需要辅助功能权限） |
| `ResultWindow.swift` | 结果窗口与内嵌 WebView |
| `HotKeyEditor.swift` | 快捷键录制界面 |
| `HelpDocument.swift` | 使用说明，按当前配置实时生成 |
| `Config.swift` | 配置模型，缺字段自动回落默认值 |
